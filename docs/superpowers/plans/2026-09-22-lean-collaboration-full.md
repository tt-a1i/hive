# Hive 协作减负：完整目标

用户要求在既有 `codex/lean-agent-communication` 分支按照完整目标推进。第一批 ask/reply/resume 已验证，继续完成下面所有边界，不以分批作为停止范围。沿用 simplify-codebase change 模式；不更换 runtime、不增加依赖、不自动扩容或更换模型。

## 真实场景和覆盖

| 边界 | 具体问题 | 可观察结果 | 不做的成本 |
| --- | --- | --- | --- |
| 问答 | 成员等待一个事实，模型反复查询和拼反向路由 | 已有 ask/reply/resume 一次调用等待、原问题恢复 | 重复调用及重复提问 |
| 邮箱与提交 | 忙时多条补充到达，逐任务维护游标、抄 seen；重启后不清楚读过哪批 | 同一未确认批次可重读，ACK 精确确认该批；新消息不被旧 ACK 吞掉，已确认消息不必再抄 seen | 丢上下文或重复读与提交 409 |
| 委派 | 实现者发现可独立拆给现有专家的子任务，必须先让主控中转 | 持有开放责任的成员可向现有成员委派；固定深度/数量上限；子报告回原委派者 | 多一轮中转 |
| 跨任务咨询 | 知识在同工作区另一任务作者手里，同 root 限制迫使主控转述 | 只放开 question 及其准确反向 answer；不读取对方整个任务树，不赋予修改所有权 | 重复调查和转述 |
| 结果 | reported 无法表示执行成功还是失败 | 派单持久化并序列化独立 outcome；沿用 success/failed，旧未知保留 null | 后续程序只能猜报告文本 |

## 实施契约

- 问题写入成功而响应丢失时，用 `team ask --list [--dispatch D] [--before Q]` 找回自己发送的问题 ID，再 resume；每页最多 50 条，返回 next_before。查询不创建消息、不授予他人消息史权限。
- 新 `team inbox [--wait 0..60]` 返回完整消息正文和 `batch_id`；同成员、同工作区未 ACK 的批次固定，重启可重放。`team inbox --ack B` 仅确认该批消息 ID，幂等，不能确认别人的批次。新消息留给下一批。读取与确认都不表示回答问题或成果验收。
- 一批最多 50 条、64 KiB 正文；单条超过预算时整条返回，不截断事实。首次只纳入当前开放责任输入及未答历史 question，不导入全部已结束历史；已经发出的批次不因任务后续关闭而换内容。
- ACK 明确声明已考虑该批输入，仍不证明理解或成果正确。它是可选入口：`report --ack B` 在同一事务内确认并报告，不强制 inbox→ACK→report 三步。若新消息导致报告失败，事务内 ACK 同步回滚。
- 外部主控继续使用已有、受宿主 thread 绑定约束的 read_reports/ack_reports 收据流，不再增加第二份邮箱；CLI inbox 不用于外部主控身份。它的 ACK 只消费通知，不能替成员确认输入。外部新增 question/reply 短入口，reply 复用 operation_id 幂等机制。
- report 继续在事务内检查新输入。显式 `--seen` 保留；省略时允许已通过 mailbox ACK 确认的输入，无新义务时直接报告。ACK 与 PTY delivered 分离；绝不把读取/写入 PTY 自动等同确认。
- 委派使用 `team delegate <member-name> --from-dispatch D <task>`，仅自己持有的开放、已投递责任，目标为已有成员，禁止自己/祖先成员形成依赖环，不自动启动停止成员、不 spawn。专用委派父链区别于已有 related-to 图：最多 2 层、每父最多 3 个开放子责任、每条顶层委派树累计最多 8 份子责任。检查和创建必须同一事务，不能并发穿透限制。
- 父责任报告前子责任必须终结，失败可由委派者取消自己的子树再报告；主控仍可取消任意责任。父取消/成员删除须退役委派后代，保留既有关联图不级联的含义；不杀共享成员进程。
- 同工作区跨 root 只开放 question/answer；source 必须自己持有且开放（历史回答例外不变），取消与控制器换绑限制仍成立。收件人从原问题推导，不能自报任意收件人。原完整任务消息读取权限不扩大；成员发现提供最少成员/责任摘要。
- outcome 单独保存 `success|failed|null`，不改变 queued/submitted/reported/cancelled 或成员三态；取消不是成功。旧记录不推断为成功。
- `report --success/--failed` 从旧 no-op 改为真实结果声明；HTTP 原 status 字段继续复用，写入 ledger，并在 HTTP dispatch、关联责任、controller inspect/read_reports 输出。委派子结果复用 dispatch_message_outbox，作为父责任的持久 note 输入；不再复制一份报告唤醒主控。主控仍从账本查看全树。
- 所有新存储走版本 46 migration。先在独立临时库验证升级、重开、批次 ACK；不触碰用户运行库。回退需配合升级前数据库备份，不删新数据伪装可逆。

## 验证与完成

用真实 HTTP/SQLite/PTY/CLI self-check 验证所有新边界、并发顺序和授权拒绝；初期受冻结限制未修改 tests/，用户恢复后已接入常规核心测试。因为涉及 migration 和协议范围，运行现有全量测试并对失败做基线区分；另跑 check/build。真实模型成本比较只有固定任务/预算/模型的实跑才能给结论，机制检查不能替代。四个独立 reviewer 按架构、边界、验证、契约评审，逐项消化反馈后写最终收据。只在本地分支实现；提交、推送、发布另行授权。

明确的验证场景：读 A→写 B→ACK A→报告仍拒绝→ACK B 才可报告；ACK 重放/越权/重启；并发 4 次委派只接纳 3 个开放子任务；祖先环/深度/总量拒绝；父报告与创建串行事务；父取消、成员删除与 pending 对齐；停止成员不自启、子结果重启投递；跨 root 问答成功而 note/整树读取/跨 workspace 拒绝；旧库升级和未知 outcome=null。外部控制器用临时 codex 通知程序（只响应 capability，不触发真实宿主通知）验证实际 MCP/HTTP 绑定、换绑后的 question closed 与 reply 拒绝。

## 变更与代价

- 减少模型维护的协议义务：回复不必重建反向路由；等待不必反复调用模型；输入确认不必逐任务抄水位；现有专家可直接接子任务或回答跨任务事实问题。
- 代码量增加：新增持久批次/收据、委派父关系与限额、outcome 和问题查询入口。运行时承接这些义务，固定限额和共享消息 outbox 控制新增复杂度。未新增依赖、调度器或第二套成员进程。
- 保留兼容：原 message/messages、显式 seen、既有关联任务树、外部主控收据流。它们仍有调用者且承担不同边界，不把它们当作死代码删除。
- 修改既有 `check-collaboration-event-guidance.ts`：只让解析匹配真实生成的短 reply，关闭自动浏览器；新增两个断言脚本。用户恢复后同步相关 tests/ 并增加集成入口、真实 SQLite 边界检查；未删除测试用例。
- 回退：源代码通过分支 diff 逐项撤销；本轮所有 migration 只运行在临时库。未来真实库升级前必须备份，回退同时恢复匹配的升级前库；不靠删除新字段清除用户历史。
